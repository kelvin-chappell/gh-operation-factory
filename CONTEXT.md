# Vocabulary

| Term | Meaning |
|---|---|
| Operation | One bounded intent applied to a set of repositories |
| Definition | Shared base, operation settings and the two supplied skill packages |
| Operator | Human authorised to approve and control the operation |
| Candidate / target | Discovered repository / candidate that passed qualification |
| Lifecycle stage | Shared checkpoint: readiness, exploration, sample, rollout or completion |
| Milestone | A target's last verified achievement; independent of its standing |
| Standing | Current work condition, such as ready, acting, proposal open or blocked |
| Generation | Identity of a target task; changes when its approved obligations change |
| Claim | Verified exclusive ownership of a target transition through reconciliation |
| Proposal | Draft pull request for one target transition; humans decide merges |
| Sample | Recorded subset used for inspection or a separately authorised pilot |
| Waiver | Human's reasoned exemption from an unfinished target obligation |
| Complete | Exhausted discovery and every qualified obligation achieved or waived |

An exploration skill defines discovery, qualification and milestone detection.
An action skill defines one bounded transition and its acceptance. The shared
runbook, not either supplied skill, governs execution.
